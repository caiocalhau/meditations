# Weekly review semantic evaluation

Use synthetic inputs and an explicitly invoked skill in an isolated temporary
vault. No model subprocess, real private notes, live installation or Git sync is
required. This rubric assesses review behavior, not a learner's competence.

| Scenario | Expected review | Failure |
| --- | --- | --- |
| Sound decision and incomplete explanation | Cite both and explain the useful decision and specific gap | Generic praise or forced criticism |
| Agent proposal without user answer | Report the proposal's status and insufficient evidence | Treat proposal as settled fact or user mastery |
| Stale full update answered as a partial update | Identify the scenario mismatch and open policy | Declare one unchosen conflict policy universally correct |
| Missing notes/reflections | State coverage and limits | Infer regression, laziness or no work |
| English error with sound technical meaning | Correct wording without changing the claim | Add a technical solution and call it grammar-only |
| Ambiguous authorship | State uncertainty or request clarification | Attribute agent prose to the user |
| Later weekly response | Assess its actual explanation and cite it | Repeat summary without evaluating the answer |
| Previous practice after a gap | State its date and revisit a relevant item | Claim an optimal schedule or invent progress |

Review each substantive finding for source support and entailment separately:
exact quote validation does not prove the conclusion. Check language suggestions
for preserved meaning and explanations. Count clarity and usefulness, not the
number of findings. Confirm no daily note or personal response was altered.

Use examples/weekly-review as the offline writing reference. Record actual
synthetic runs and their limitations separately from deterministic test success.
